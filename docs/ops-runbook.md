# AAIS Operations Runbook

This runbook keeps release evidence redacted: record variable names, environment names, status, and timestamps, but never copy secret values.

AAIS production is deployed on Vercel and uses Neon Postgres. Release evidence must prove the expected Vercel deployment URL, a redacted Vercel platform signal, and the restored Neon database provider without storing any database URL or credential value.

## Pre-Release Gate

1. Run `npm ci`.
2. Run `npm run ci`.
3. Run `npm run verify:vercel-env -- --environment production --auth-mode sso-only --ai-mode live --output <redacted-vercel-env-report-path>` and confirm the report has `status: "passed"`; if it fails, use the redacted `provisioningPlan.actions` command skeletons to add missing Vercel variable names without putting values in the report. To generate an owner-fillable shell for the missing Neon/OIDC values, run `npm run release:env-template -- --vercel-env-report <redacted-vercel-env-report-path> --base-url <vercel-deployment-url> --release-id <release-id> --deployment-git-commit <git-sha> --output <private-env-template-path> --report <redacted-template-report-path>`; the template may prefill non-secret `AAIS_RELEASE_ID` and `AAIS_DEPLOYMENT_GIT_COMMIT_SHA`, while OIDC/Neon placeholders still fail closed until replaced.
4. If the missing values are in a local owner-provided env file, run `npm run verify:oidc-config -- --env-file <private-env-file> --base-url <vercel-deployment-url> --output <redacted-oidc-config-report-path>` first and confirm `status: "passed"` before applying OIDC values to Vercel. This report records only missing names, placeholder names, redirect/discovery booleans, partial explicit endpoint override status, role-mapping source names, and safe failure categories; it must not include mapped emails, mapped groups, endpoint URLs, or OIDC secret values.
5. Run `npm run provision:vercel-env -- --env-file <private-env-file> --report <redacted-vercel-env-report-path> --release-id <release-id> --deployment-git-commit <git-sha> --output <redacted-provision-dry-run-path>` and confirm `status: "ready"`; then run the same command with `--apply` and archive the redacted apply report. `--release-id` and `--deployment-git-commit` can satisfy the non-secret `AAIS_RELEASE_ID` and `AAIS_DEPLOYMENT_GIT_COMMIT_SHA` even when the private env file contains only owner-managed provider values. For the Neon storage slot, the private env file may use `AAIS_DATABASE_URL`, Vercel/Neon `DATABASE_URL`, `POSTGRES_URL`, `POSTGRES_PRISMA_URL`, `DATABASE_URL_UNPOOLED`, `POSTGRES_URL_NON_POOLING`, raw `PGHOST` or `PGHOST_UNPOOLED` plus `PGUSER`, `PGDATABASE`, and `PGPASSWORD`, or legacy `POSTGRES_HOST` or `POSTGRES_HOST_NON_POOLING` plus `POSTGRES_USER`, `POSTGRES_DATABASE`, and `POSTGRES_PASSWORD`; if matching raw port or sslmode variables are present, the provisioner carries them along too. Template placeholders such as `<REQUIRED:NEON_POSTGRES_URL>` intentionally count as missing until replaced. The provisioner sends values to Vercel through stdin and records only variable names, command skeletons, and statuses.
6. If the apply report has `status: "applied"`, run `vercel deploy --prod -y --no-wait`, then `npm run verify:vercel-deployment -- --deployment-url <deployment-url> --release-id <release-id> --deployment-git-commit <git-sha> --output <redacted-vercel-deployment-report-path>` against the returned deployment URL; Vercel environment changes are not proven in the runtime until a fresh Production deployment, `READY` inspect evidence, source commit evidence, and smoke verification complete.
7. Re-run `npm run verify:vercel-env -- --environment production --auth-mode sso-only --ai-mode live --output <redacted-vercel-env-report-path>` and confirm the report has `status: "passed"`.
8. Confirm Vercel production has `AAIS_SESSION_SECRET`, one Neon-backed database source (`AAIS_DATABASE_URL`, `DATABASE_URL`, `POSTGRES_URL`, `POSTGRES_PRISMA_URL`, `DATABASE_URL_UNPOOLED`, `POSTGRES_URL_NON_POOLING`, raw `PGHOST`/`PGUSER`/`PGDATABASE`/`PGPASSWORD` pieces, or legacy `POSTGRES_HOST`/`POSTGRES_USER`/`POSTGRES_DATABASE`/`POSTGRES_PASSWORD` pieces), `AAIS_DATABASE_PROVIDER=neon` or a `.neon.tech` database host, LRS variables, OIDC variables, at least one configured teacher/admin OIDC role mapping (`AAIS_OIDC_TEACHER_GROUPS`, `AAIS_OIDC_TEACHER_EMAILS`, `AAIS_OIDC_ADMIN_GROUPS`, or `AAIS_OIDC_ADMIN_EMAILS`), and any live-AI variables set. If the Vercel env verifier reports missing `AAIS_OIDC_TEACHER_GROUPS`, it means no accepted educator mapping source is present; the private env provisioner may satisfy that request with any one of the accepted mapping variables. Keep `AAIS_TRIAL_ACCOUNTS_JSON` set while trial login is enabled; set `AAIS_TRIAL_LOGIN_ENABLED=false` only after SSO-only access is verified.
9. If `AAIS_AI_PROVIDER=openai-compatible` in production, confirm `AAIS_AI_EVAL_APPROVED=true`, `AAIS_AI_EVAL_VERSION` points to the reviewed model evaluation record, and either `AAIS_AI_EVAL_MANIFEST_JSON` contains the matching redacted inline JSON manifest or `AAIS_AI_EVAL_MANIFEST_PATH` points to a server-readable passing JSON manifest.
10. Request `/api/system/readiness` and confirm it returns `200` with `status: "ready"`, `checks.trialAccounts.status: "ok"` while trial login is enabled or `"disabled"` for SSO-only production, `checks.storage.provider: "neon"`, `checks.storage.sourceEnv` set to the database source in use, `checks.storage.probe: "connected"` for Neon Postgres deployments, `checks.oidc.status: "ok"`, and `checks.oidc.roleMapping.status: "ok"` with only accepted role-mapping variable names recorded.
11. If readiness reports file storage or a missing database source in production, treat learner-session APIs returning `503` as the expected fail-closed behavior; do not run learner smoke tests until Neon/Postgres is configured.
12. Run `npm run verify:enterprise -- --base-url <deployment-url> --require-sso-only --release-id <release-id> --output <redacted-enterprise-report-path>` and archive the redacted JSON output.
13. Confirm the verifier reports `readiness` and its production subcheck details as `passed`.
14. Confirm the verifier reports `legal-pages` as `passed`, with `/terms` and `/privacy` returning `200`, HTML content, and redacted content-presence booleans.
15. Confirm the verifier reports `lrs-health` as `passed`.
16. If an online check fails before evidence is collected, use the safe `details.errorCategory` enum to distinguish deployment reachability issues such as `connect-timeout`, `response-timeout`, `dns`, `tls`, or `network` from application-level failed checks; do not ask for or archive raw error messages.
17. In staging, with trial smoke variables set, confirm the verifier reports `trial-learning-session` as `passed`.
18. After the Vercel env preflight, source provenance report, Vercel deployment `READY` inspect report, live-AI evaluation, OIDC callback smoke, SSO-only smoke, and Neon Postgres restore rehearsal are complete, run `npm run verify:enterprise-release -- --base-url <vercel-deployment-url> --release-id <release-id> --deployment-git-commit <git-sha> --source-provenance-report <redacted-source-provenance-report-path> --vercel-env-report <redacted-vercel-env-report-path> --vercel-deployment-report <redacted-vercel-deployment-report-path> --enterprise-report <redacted-enterprise-report-path> --release-evidence-output <redacted-release-evidence-path> --ai-eval-manifest <server-readable-manifest-path> --postgres-restore-report <redacted-restore-report-path> --deployment-url <vercel-deployment-url> --deployment-platform vercel --database-provider neon --output <redacted-enterprise-release-check-path> --max-age-hours 168`.
19. Confirm the enterprise release check summary and final release evidence report both have `status: "passed"` before sign-off.
20. If the enterprise release check fails because owner-managed Vercel/Neon/OIDC values are missing, run `npm run release:handoff -- --release-check-report <redacted-enterprise-release-check-path> --source-provenance-report <redacted-source-provenance-report-path> --vercel-env-report <redacted-vercel-env-report-path> --provision-report <redacted-provision-dry-run-path> --base-url <vercel-deployment-url> --release-id <release-id> --deployment-git-commit <git-sha> --ai-eval-manifest <server-readable-manifest-path> --postgres-restore-report <redacted-restore-report-path> --output <redacted-enterprise-handoff-path> --markdown-output <redacted-enterprise-handoff-md-path>` and send only the generated handoff, never any secret values. The handoff points to the private env template and restored-Neon template, recognizes any accepted educator OIDC role-mapping variable name in local credential inventory, and includes the OIDC config dry-run, safe provision dry-run/apply, restore rehearsal commands, real OIDC callback smoke before the SSO-only cutover, source provenance path, deployment commit input, and direct `vercel env add` skeletons.
21. Run `npm run release:audit -- --release-check-report <redacted-enterprise-release-check-path> --handoff-report <redacted-enterprise-handoff-path> --output <redacted-enterprise-audit-path> --markdown-output <redacted-enterprise-audit-md-path>` to archive the readiness pass/action-required matrix for release review, including the scheduled outbox drain control.
22. Run `npm run release:bundle -- --source-provenance-report <redacted-source-provenance-report-path> --vercel-env-report <redacted-vercel-env-report-path> --vercel-deployment-report <redacted-vercel-deployment-report-path> --enterprise-report <redacted-enterprise-report-path> --release-evidence-report <redacted-release-evidence-path> --release-check-report <redacted-enterprise-release-check-path> --handoff-report <redacted-enterprise-handoff-path> --readiness-audit-report <redacted-enterprise-audit-path> --oidc-config-report <redacted-oidc-config-report-path> --ai-eval-manifest <server-readable-manifest-path> --postgres-restore-report <redacted-restore-report-path> --release-id <release-id> --output <redacted-release-bundle-path> --markdown-output <redacted-release-bundle-md-path>` to create the hash manifest for the evidence bundle.
23. Prefer `npm run release:refresh -- --base-url <vercel-deployment-url> --release-id <release-id> --deployment-git-commit <git-sha> --env-file <private-env-file> --ai-eval-manifest <server-readable-manifest-path> --postgres-restore-report <redacted-restore-report-path> --output <redacted-release-refresh-path> --max-age-hours 168` when refreshing the whole redacted evidence chain; it runs step 18, private env template generation, restored-Neon template generation, OIDC config dry-run, provision dry-run, handoff, audit, and bundle generation in order and exits non-zero while any artifact remains action-required.

## SSO Smoke

1. Request `/api/auth/oidc/start?from=/learning`.
2. Confirm the response is `307`.
3. Before applying IdP values, run `npm run verify:oidc-config -- --env-file <private-env-file> --base-url <staging-or-production-url> --output <redacted-oidc-config-report-path>`; if explicit endpoint overrides are absent, this dry-run confirms the issuer's `/.well-known/openid-configuration` document is reachable.
4. Confirm `location` points to the approved IdP authorization endpoint and includes `response_type=code`, `client_id`, `redirect_uri`, `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`, and an `openid` scope.
5. Confirm `aais_oidc_state` is `HttpOnly`, `Secure`, and `SameSite=Lax`.
6. Confirm `/terms` and `/privacy` render from the login consent links so institutional users do not hit a compliance dead link.
7. Complete one real IdP callback in staging and confirm AAIS sets `aais_session` and `aais_csrf` without storing authorization codes or ID tokens in cookies.
8. For redacted callback evidence, set transient `AAIS_VERIFY_OIDC_CALLBACK_URL` and `AAIS_VERIFY_OIDC_STATE_COOKIE` from the same staging login, then run `npm run verify:enterprise -- --base-url <staging-url> --release-id <release-id> --output <redacted-enterprise-report-path>` and confirm `oidc-callback` reports `passed`, including `learningSessionStatus: 200` and `learningSessionReadable: true`. Do not run the handoff command with `<REQUIRED:TRANSIENT_...>` placeholders unchanged; the verifier treats them as local failure, not evidence.
9. Do not store the callback URL, authorization code, state value, or state cookie after the smoke completes.
10. For SSO-only production, set `AAIS_TRIAL_LOGIN_ENABLED=false`, confirm `/login` no longer renders the trial account form, and confirm `/api/auth/app-session` returns `404`.
11. Run `npm run verify:enterprise -- --base-url <staging-url> --require-sso-only --release-id <release-id> --output <redacted-enterprise-report-path>`.
12. Confirm `npm run verify:enterprise` reports `oidc-start` and `sso-only-mode` as `passed`.

## Trial Login Abuse Smoke

1. On staging only, set `AAIS_VERIFY_TRIAL_ACCOUNT`, `AAIS_VERIFY_TRIAL_CORRECT_PASSWORD`, `AAIS_VERIFY_TRIAL_WRONG_PASSWORD`, and `AAIS_VERIFY_TRIAL_CLIENT_IP`.
2. Run `npm run verify:enterprise -- --base-url <staging-url> --release-id <release-id> --output <redacted-enterprise-report-path>`.
3. Confirm `trial-learning-session` reports `passed`; this verifies a correct trial login sets `aais_session` plus `aais_csrf`, then reads `/api/learning/session` for the signed learner.
4. Confirm `trial-login-throttle` reports `passed`; this submits five wrong passwords, confirms a sixth wrong password returns `429` with `Retry-After`, then confirms the correct password stays blocked and does not set `aais_session`.
5. Confirm audit logs include `rate_limited` without password values.

## Enterprise xAPI Event Model

1. Treat the LRS as the learning-behavior fact layer, not the LMS or HRIS source of truth.
2. Keep AAIS xAPI statements in the product language: `session_id`, `phase`, `task`, `agent`, `event`, `time`, and redacted `detail`.
3. Verify A1 events cover expert modeling, understanding checks, task release, and guide response completion.
4. Verify A2 events cover planning/artifact evidence, AI prompts, monitoring signals, AI acceptance, and coaching pushes.
5. Verify A3 events cover articulation, self-report, and expert-trace comparison.
6. Verify A4 events cover scaffold requests and the fifth-request self-check transition.
7. Use cohort, role, course id, phase, task, agent, and event as LMS/HRIS/BI join keys; do not export provider secrets, raw prompts, artifacts, self reports, cookies, or tokens into LRS statements.
8. Keep learner-session persistence on the fast path and LRS mirroring in the persistent Postgres outbox plus asynchronous retry queue so network or LRS failures do not block learning interactions.
9. Monitor persistent outbox counts in health/readiness so pending/retry/dead-letter growth is visible without reading raw xAPI payloads.
10. Keep a controlled batched drain path for the persistent outbox so serverless interruptions do not rely only on fire-and-forget in-process flushing or one network call per xAPI statement.
11. Debounce high-frequency artifact autosaves in the learner UI, flush the pending save when the learner leaves the editor, and coalesce again before LRS delivery; the API and LRS should receive the latest `artifact_edited`, `artifact_saved`, and `planning_submitted` facts with merge metadata instead of every keystroke.
12. Treat A2 `monitoring_pause_detected`, `coaching_push`, and keyed `ai_acceptance_recorded` as first-class evidence for teacher dashboards and later BI/LMS joins; count unique AI acceptance decision keys as interaction evidence, allow explicit decision revisions, and keep learner rationale text plus raw message ids out of analytics and LRS statements.

## Backup And Restore

For file-backed development or controlled single-node runs:

1. Run `npm test -- tests/aais-backup.test.ts`.
2. Confirm the backup manifest includes a session count and SHA-256 checksums.
3. Confirm restoring the manifest into a clean data directory preserves learner artifacts.

For production Neon Postgres:

1. Take a managed database snapshot before deployment.
2. Restore that snapshot into staging.
3. Generate the restored-Neon template with `npm run release:restore-template -- --output <restore-template-output-path> --report <redacted-restore-template-report-path> --postgres-restore-report <redacted-restore-report-path> --release-id <release-id>`.
4. Copy that template to `.env.postgres-restore.local`, set `AAIS_RESTORE_DATABASE_URL` in the copy to the restored staging database, not any production database source such as `AAIS_DATABASE_URL`, `DATABASE_URL`, `POSTGRES_URL`, or raw `PG*`/`POSTGRES_*` pieces, then run `npm run verify:postgres-restore -- --env-file ./.env.postgres-restore.local --database-provider neon --output <redacted-restore-report-path> --release-id <release-id>`.
5. Confirm the command accepted the restored database URL as a Neon host, and the report has `status: "passed"`, `target.provider: "neon"`, `checks.tablePresent: true`, `checks.smokeReadBack: true`, `checks.smokeDeleted: true`, and `target.databaseUrl: "redacted"`.
6. Point staging `AAIS_DATABASE_URL` at the restored database.
7. Run the Learning Data And LRS smoke, excluding any write to the production LRS.
8. Record the snapshot id, staging restore report path, staging smoke status, and smoke timestamp.
