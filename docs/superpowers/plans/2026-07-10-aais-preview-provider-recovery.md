# AAIS Preview Provider Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover AAIS Preview E2E on the real protected Vercel project with an isolated Neon database, a three-stage trust gate, zero secret-bearing artifacts, generation-2 evidence, and lossless closure.

**Architecture:** A reviewed 17-path code slice is built from sealed head `107bc717065b534fb71d009a969217cc573eb885`, then integrated locally into the existing compose branch. Weak secrets are quarantined before a two-path default-main trust bootstrap; only after the reviewed candidate, metadata-only provider preflight, and Stage A/B attestation may isolated Preview resources and strong credentials be created. External mutations, evidence, publication, credential cleanup, and root/worktree closure remain sequential, fail closed, and independently reviewed.

**Tech Stack:** TypeScript, Node.js, PostgreSQL migrations, `pg`, Playwright, Vitest, GitHub Actions/CLI/API, Vercel API, Neon API, Git worktrees.
