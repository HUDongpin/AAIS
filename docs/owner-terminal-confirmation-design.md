# 不依赖生物识别的 Owner 操作确认：方案与审查

> 后续进展：已实现独立的 [无凭据终端确认原型及测试](terminal-confirm-prototype.md)。
> 本页保留设计阶段原文；下文“未实施”描述的是当时状态，不适用于新原型。
> 新原型尚待Owner交互验收，真实凭据入口与生产能力仍未激活。

2026-09-08：**方案已完成本地审查，但未实施、未启用，也未通过独立安全审查。**
本文件是独立替代方案，不是修改 Touch ID 程序的降级路径。真实凭据入口继续关闭。
不新增硬件要求，不要求 Owner 配置 Touch ID、改用系统密码认证或降低系统保护。

  TTY、代码身份及系统 login 链检查通过。这是该次用户提供的观察证据，不是新会话授权。

  不能解析旧 JSON、接收 caller-supplied `originOK` 或用前次成功代替。

## 2. 最小方案：仅确认一个明确显示的操作

第一版应为**独立、原生、无凭据、无网络、无签名**的终端确认原型，与 Touch ID 实验分开。
它只验证用户交互，不构建服务器授权协议。尚未在本轮实现，也没有可运行的新命令。

拟定流程：

1. Owner 亲自从独立系统 Terminal 启动；复用已验证的原生来源规则、精确代码身份、
   双快照、UID 转换规则、同一前台控制 TTY。不能由 Codex/IDE 创建终端或伪装启动来源。
2. 使用一个不可变的操作结构。无凭据原型明确标注 `offline-fixture-only`；
   真实生产版本的目标必须来自独立核验、审核过的绑定，不能用 fixture 值填补缺失字段。
3. 在终端清楚显示全部范围：AAIS、操作类型、实例/地域、服务器主机身份指纹、
   镜像仓库、完整 SHA、完整 digest，以及本次操作不会做什么。
   对预加载而言，应明确“不启动容器、不改数据库/Vercel/DNS”。字段中拒绝控制字符、
   ANSI 转义、超长文本、换行注入和未知字段，避免屏幕显示内容与内部操作不一致。
4. 显示本次随机确认短语，例如 `CONFIRM AAIS <本次随机码>`。它不是密码、token 或密钥，
   不具有身份认证意义，不可用于服务器登录。只有逐字相同的完整一行才表示确认；
   Enter、空白、yes、部分匹配均不自动通过。无需密码或生物识别。
5. 只从本次控制 TTY 接收有上限的一行非秘密文本（拟定 128 字节、60 秒单调时钟窗口）。
   不接受参数、环境变量、文件、管道、stdin 重定向、剪贴板 API 或旧收据的自动确认。
   不读取或保存其他终端内容；不在输出或日志回显原始输入。
6. 确认后再核对来源、前台 TTY、时间及原不可变操作；任何变化即取消。
   一个会话至多一次确认，无自动重试。取消、EOF、超时、Ctrl-C、后台切换、超长输入或
   断线均结束本次会话。不得静默清掉缓冲内容以假装取消成功或重新授权。
7. 原型只输出 `operationConfirmed`、固定失败码及
   `authorizesLiveExecution=false`、`hardwareIdentityVerified=false`、
   `signingKeyProtectionVerified=false`、`credentialsRead=false`。
   不输出服务器可接受的签名/票据，不进入密码提示，不执行任何操作。

若实现时暂时改变终端模式，必须定义正常、取消、异常恢复路径并测验；优先不改变回显模式，
因为这里输入的是公开的确认短语，不是凭据。真实凭据仍只能在将来已审查的流程中由 Owner
在隐藏提示亲自输入，本方案没有提前授予读取、收集、传输或保存凭据的权限。

## 3. 审查结论：这不是身份认证或密钥保护

普通终端输入只能形成“当前程序收到了与显示操作绑定的确认文本”的软件证据。
它不能证明键盘前是谁、阻止同 UID 恶意进程、证明硬件用户在场，或保护一个签名私钥。
终端粘贴也无法从文本内容可靠区分人工输入；不要声称随机短语解决了这一点。
原生来源检查仍不能重建已结束的历史祖先或证明人类意图，既有威胁限制全部保留。

因此：

- **允许继续原型验证**：适配现有无 Touch ID 设备，明确显示操作，Owner 明确确认，
  取消/超时/变化则拒绝。不得自动连接真实凭据流程。
- **不能放行生产**：不把确认短语、`operationConfirmed=true` 或旧 launch-check JSON
  当成远端授权，不生成假签名收据，不提供 `ALLOW_OWNER=true`。
- **服务器认证独立**：真实操作必须有已核验主机身份和最小权限的服务认证。
  本轮未选择或注册 SSH key、PAT、公钥信任根，也未获准改变服务身份。
- **不强制新增应用签名协议**：此前双端签名方案保留为历史候选，不自动要求它成为唯一
  生产路线。可以另行审查受限现有服务认证是否已满足要求；但不能因此跳过认证或在
  未审核情况下包装、替换现有 Owner launcher。具体传输方案仍是未关闭的门槛。

## 4. ECS 接收端影响与继续封堵

现有 `aais-preload-ghcr-image.sh` 主入口仍在读配置、凭据提示、Docker login 前无条件拒绝。
此文档不授权删除该门，旧 `owner-launcher-plan.json` 的执行开关和 null 绑定不变。

新方案不能直接接入现有脚本。此前 [ECS 审查](ecs-owner-receiver-review.md) 中的
精确目标、受限入口、真实来源验证、秘密传输、崩溃清理和失败不得写成功收据仍然适用。
“签名 challenge/签名 key 注册”是旧方案特有的候选设计，不是已存在的安全能力；如果选择
其他服务认证，应单独审查同连接范围、重放/重复操作控制与权限，并记录为何足够。
既不能为了迎合旧方案无限增加自定义安全系统，也不能用普通确认冒充服务端信任根。

## 5. 下一轮原型应满足的验收矩阵（尚未执行）

| 场景 | 要求 |
| --- | --- |
| 完整来源＋精确显示＋正确短语 | 仅本次离线 operationConfirmed，真实执行仍 false |
| 禁止/未知来源、root 非法节点、UID/代码身份变化 | 在确认输入之前拒绝 |
| 空白/部分/错误/旧随机码、参数/环境放行 | 拒绝，不自动重试 |
| 显示后的实例/SHA/digest/操作变化 | 拒绝，不复用先前确认 |
| ANSI/控制字符/换行/超长字段 | 显示前拒绝，防止误导用户 |
| 取消/超时/EOF/Ctrl-C/断线/后台切换 | 结束；无 key、无凭据、无成功操作 |
| 两次确认或迟到输入 | 第二次无效，不能重新打开会话 |
| JSON 声明 true、假收据、旧生物识别结果 | 不作为输入或授权依据 |
| 回归 | 旧原生来源规则、生物识别程序和凭据封堵门保持完整 |

自动测试使用分离的纯状态/输入解析核；不得运行凭据 launcher 或操纵 Terminal.app。
Owner 正向、取消及超时验收仅针对无凭据原型。生产接通需要另一次明确授权与独立审查，
不是原型测试通过的自动后果。

## 6. 本轮变更范围

只新增替代路线状态文件、方案/审查及隔离回归断言，更新旧文档的状态指示。
不实现交互程序、不启动 Touch ID 演示、不读取凭据、不联网到 provider，不修改原生来源
代码、生物识别策略、GHCR、数据库或 Vercel。无需要 Owner 现在复制执行的命令。
