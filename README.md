# AAIS

AAIS is a focused Cognitive Apprenticeship learning system with four product agents:

- `A1` Guide Agent for CA flow orchestration, four direct scaffold opportunities per task, and fading support.
- `A2` Expert Agent for two-expert Modelling demonstrations and Coaching dialogue, including `@` expert selection.
- `A3` Supervision Agent for backend behavior-data collection, A1 scaffold signals, and A1 handoff.
- `A4` Reflection Agent for articulation records, reflection reports, reflective prompts, and expert comparison.

The runtime CA background is centralized in `aaisCognitiveApprenticeshipBackground`. It defines the AAIS sequence as Modelling, Coaching, Scaffolding, Articulation, and Reflection, with Fading tracked as A1's scaffold-reduction contract. LangGraph passes this background to every A1-A4 model turn so live providers and deterministic fallbacks share the same Cognitive Apprenticeship frame.

Production AAIS is deployed on Vercel and uses Neon Postgres for learner-session persistence.

The enterprise gate runs lint, full TypeScript checking, unit tests, and a production build.
The current-stage enterprise verifier checks the deployed readiness endpoint and production subchecks for trial auth, security headers, `/terms` and `/privacy` legal pages, LRS read-only health, trial learning-session access, trial-login throttling, teacher cohort analytics, and the A1-A4 evidence contract without printing secrets or cookies. SSO/OIDC checks are available only when explicitly running the future `--auth-mode sso-only` / `--require-sso-only` gate.
The release evidence verifier checks that the clean source-provenance, archived Vercel production environment preflight, Vercel deployment, live-AI, and Neon restore artifacts are present, fresh, from the same release candidate where applicable, mutually compatible, redacted, secret-scan clean, and passing, including static legal-page evidence, A3 supervision plus A2 coaching capability evidence, the Vercel Cron outbox drain configuration, a redacted Vercel platform signal, enterprise smoke evidence generated after the latest Vercel env preflight and Vercel deployment READY inspect, source commit alignment with deployment evidence, a deployed-model fingerprint match for the live AI evaluation, and per-agent A1-A4 live-AI coverage that matches the current Cognitive Apprenticeship role contract.
The enterprise release check runner sequences the clean source-provenance check, Vercel env preflight, Vercel deployment READY inspect, deployed enterprise smoke, and final release evidence verifier in that order, then writes a small redacted gate summary whose pass/fail status follows the final release evidence report, including the scheduled Vercel Cron outbox drain evidence.
`npm run release:env-template` generates an owner-fillable private env template from the missing Vercel Production names plus a redacted report; it can prefill non-secret release metadata, suggests the accepted Vercel/Neon database sources, and when `--gap-evidence-report` points to a redacted enterprise gap preflight it adds missing `AAIS_AI_*` inputs as local evidence-only variables for live A1-A4 AI evaluation. `<REQUIRED:...>` placeholders for Neon/trial/live-AI provider values intentionally fail closed in `npm run provision:vercel-env` or the local evidence preflight until replaced with real values.
`npm run verify:oidc-config` and `npm run prepare:oidc-sso` remain available for a future SSO-only cutover, but they are not part of the current trial-auth gate.
`npm run release:restore-template` generates an owner-fillable restored-Neon env template plus a redacted report; copy the template to `.env.postgres-restore.local`, fill the copy with the restored staging Neon URL, keep `AAIS_RESTORE_TARGET_PURPOSE=restored-staging`, then `npm run verify:postgres-restore -- --env-file ./.env.postgres-restore.local --source-env-file ./.env.production.local --target-purpose restored-staging` reads the restored database URL transiently and still emits only redacted evidence. When the private source env file exists, the verifier compares normalized production sources against the restore target without serializing either URL.
`npm run release:gap-template` generates an owner-fillable `.env.enterprise-smoke.local` template for trial learner and educator smoke inputs used by `verify:enterprise-gaps`, plus safe command skeletons for trial auth, restored Neon rehearsal, live A1-A4 AI eval evidence, and the combined current-stage `all` gate. The generated report stores only placeholder variable names, output paths, and safe command skeletons.
`npm run verify:enterprise-gaps` is a fail-closed wrapper for the remaining external enterprise evidence. For the current stage, use `--mode trial-auth`, `--mode restore`, `--mode live-ai-eval`, or `--mode all` once `.env.enterprise-smoke.local`, `.env.postgres-restore.local`, and the private live-AI env file are ready. The `oidc-callback` and `cohort-sso` modes are reserved for a future explicit SSO-only cutover. Add `--preflight-only` when you only want a redacted readiness check for the inputs; preflight mode never opens the restore database or calls the AI provider, and returns `preflight-ready` instead of final evidence. It reads `.env.enterprise-smoke.local`, `.env.postgres-restore.local`, and the configured AI eval env file transiently, rejects `<REQUIRED:...>` placeholders, writes only status summaries, and never serializes database URLs, provider endpoints, model ids, model replies, or provider secrets.
`npm run backup:file` and `npm run restore:file` provide a controlled file-storage disaster-recovery path for local or single-node AAIS data directories: the private manifest contains learner-session payloads and checksums, while the report records only status, paths, counts, hashes, and redaction markers.
If the enterprise release check fails because owner-managed Vercel/Neon/trial/live-AI values are absent or current production evidence is not traceable, `npm run release:handoff` generates a JSON and Markdown action list with variable names, granular redeploy reasons such as missing deployment git commit evidence, private env template paths, safe dry-run/apply command skeletons, gap preflight command skeletons, final gap evidence command skeletons, and local credential-file name inventory only. SSO-only actions appear only when the evidence is explicitly targeting `authMode: "sso-only"`.
`npm run release:audit` turns the final gate, handoff, and optional gap evidence preflight into a control readiness matrix. The current trial gate has four business gap groups: restored Neon rehearsal, teacher cohort analytics, A1-A4 agent evidence, and current release consistency. Explicit SSO-only evidence adds production OIDC config, real OIDC callback, and SSO-only cutover groups.
`npm run release:bundle` creates a redacted evidence-bundle manifest with each artifact path, reported status, effective status, SHA-256 hash, and secret-scan issue name, including the enterprise gap template report and enterprise gap evidence report; it exits non-zero while any required artifact is missing, action-required, or secret-scan failed.
`npm run release:refresh` runs the enterprise release check, restored-Neon template generation, enterprise gap template generation, optional `--enterprise-gap-preflight-only`, private env template generation, Vercel env provision dry-run, handoff, readiness audit, and evidence bundle in sequence so all release artifacts and owner-action inputs are refreshed from the same current state. Pass `--include-oidc-config` only for an explicit future SSO-only refresh.

## Security Notes

## Learning Analytics And xAPI

AAIS treats the Learning Record Store as the learning-behavior fact layer. Server events use a fixed Cognitive Apprenticeship model:

- A1 guides the CA flow, manages capped scaffold opportunities, and fades from direct help into dialogue-first support.
- A2 presents two-expert Modelling and Coaching interactions; learners can call a specific expert with `@`.
- A3 collects task behavior data in the backend and sends scaffold signals to A1.
- A4 collects articulation evidence through A1 prompts, returns reflection reports, asks reflective questions, and compares student traces with expert traces.
- Platform events record session lifecycle, stage navigation, task selection, and task completion.

The learner summary at `/api/learning/analytics` focuses on teaching action: training-to-practice progress, scaffold dependency, reflection evidence, coaching/AI interaction signals, and integration join keys.
